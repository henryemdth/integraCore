## Product form improvements: duplicate-name warning + category typeahead

**Analysis summary (observations confirmed):** no product-name check exists anywhere today (backend `create()` validates SKU only → 409 `SKU_EXISTS`; DB has `name TEXT NOT NULL` with no UNIQUE; the Excel import ignores duplicate names too). The Category field is a plain free-text `<Input>` even though `GET /api/products/categories` already exists and nothing consumes it. Two adjacent latent bugs get fixed along the way: the edit form loads products via `?limit=100` + `find()` (breaks past 100 products; there is no `GET /api/products/:id`), and ProductListPage derives category filter options from a capped 100-product fetch.

**Decisions (confirmed with you):** duplicate name → soft, non-blocking warning showing the existing matches; category → creatable combobox on `SearchableSelect` (suggests existing, allows new). Names deliberately stay non-unique in the DB (legitimate same-name variants remain possible; no backend `NAME_EXISTS` error, no import-path change in this phase).

### Implementation

1. **`frontend/src/lib/text.ts` (new)** — extract `normalizeForSearch(s)` (lowercase, NFD diacritic strip, trim, collapse spaces); refactor `searchable-select.tsx`'s inline diacritic filter to use it (behavior identical, one canonical implementation).

2. **`SearchableSelect` creatable mode** (`frontend/src/components/ui/searchable-select.tsx`) — new optional props `creatable?: boolean` and `placeholder?: string` (trigger text when value is empty; default-off keeps the 3 filter usages untouched). Track the cmdk input text; when creatable and the typed text has no normalized match among options, render a pinned "Use \"<text>\"" item that selects the raw string; when it normalized-matches an existing option, no create item appears (typing "BEBIDAS" surfaces "Bebidas" to pick). Trigger shows the raw value when it matches no option, placeholder when empty.

3. **Duplicate-name warning** (`ProductFormPage.tsx`) — fetch all products once on mount (`GET /api/products?limit=10000`, the pattern already used by the sales stats query); debounce 400 ms on `name`; when normalized length ≥ 2, flag bidirectional substring matches on `normalizeForSearch` (catches "cafe" vs "Café", "Café" vs "Café Especial 500g"), excluding the current product in edit mode; render a non-blocking warning `Alert` under the Name field listing up to 3 matches as "name — SKU, category, price". Saving stays allowed.

4. **Category typeahead** — ProductFormPage queries `GET /api/products/categories` and replaces the Input with the creatable `SearchableSelect`; empty value stays valid (category remains optional, Zod default `""`).

5. **Adjacent fixes** — backend `GET /api/products/:id` (authenticate, `productService.getById`, 404 code `PRODUCT_NOT_FOUND` reusing the existing key) so the edit form fetches one product directly; ProductListPage category filter switches to `/api/products/categories`.

6. **i18n** — new keys in en/es kept in parity: `products.createForm.duplicateNameTitle`, `duplicateNameItem` ({{name}}/{{sku}}/{{category}}), `useValue` (Usar "<value>"), `noCategory` (if a clear affordance is needed).

7. **Tests + verification** — backend unit test for `getById` (found/404) in the existing product service test file; full suite + `tsc --noEmit` + `typecheck:test`; frontend lint + `tsc -b` + vite build; en/es key parity check; GUI pass on the isolated seeded env (duplicate-name warning triggers on "cafe", category suggests "Bebidas" for "beb", "Use \"X\"" flow creates a new category, edit form loads, filters unaffected) with screenshots; MEMORY.md Phase 31 entry.
