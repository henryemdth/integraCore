## Electron build review → robustness fixes (server + client main process)

**Review conclusion:** the historical Windows 11 errors were genuinely fixed (better-sqlite3 ships outside the asar with its Windows prebuilds; data lives in writable `AppData\Roaming`; the backend is a single bundled CJS forked under Electron's own Node — no Node.js install needed). What remains weak is runtime robustness and the failure experience, which this phase fixes. Code signing (SmartScreen) needs a purchased certificate — documented, not codeable.

### Implementation (electron/src only + README)

**1. Single-instance lock** (both `server.ts` and `client.ts`): `app.requestSingleInstanceLock()` — a second launch quits itself and the first instance focuses its window (`second-instance` event). Kills the two-Server-launches-fight-over-port-3001-and-SQLite scenario.

**2. Bounded start retries + native error dialog** (`server.ts`): `startBackend()` gains a retry wrapper (3 attempts with increasing delay); on exhaustion it kills the forked process and shows `dialog.showErrorBox` explaining the two likely causes (port 3001 already in use — e.g. another integraCore Server; or antivirus blocking) and where the log file lives, then quits. No more infinite zombie-fork loops.

**3. Mid-session crash-loop surfacing**: an unexpected backend exit still restarts with backoff, but after 5 consecutive failed restarts the same error dialog appears and the app quits instead of spinning silently forever.

**4. Window shows a "Starting…" splash until the backend is healthy**: `createWindow()` immediately loads a small inline-styled starting page (data URL, no assets); once `startBackend()` succeeds the real `frontend/dist/index.html` is loaded. The user never sees a broken login during startup, and a fatal failure ends in the dialog, not a dead white screen.

**5. File logging**: main-process logs and the forked backend's stdout/stderr append to `userData/logs/server-main.log` (client: `client-main.log`), with simple 1 MB rotation (rename to `.old`). Makes Windows failures diagnosable at all.

**6. README "Installing on Windows" section**: SmartScreen on unsigned installers ("More info → Run anyway"), the Windows Defender firewall prompt on the Server (must be allowed for LAN clients), where data/logs live, and that port 3001 must be free. Also documents that the CI-provided `backend/.env` is not part of the installer (server settings are built-in: per-install JWT secret, CORS `*`, SQLite in userData).

### Verification
`npm run build -w electron` (tsc) + root `tsc --noEmit` for the electron project; the packaging itself is exercised by the existing GitHub Actions windows build. No frontend/backend behavior changes.
