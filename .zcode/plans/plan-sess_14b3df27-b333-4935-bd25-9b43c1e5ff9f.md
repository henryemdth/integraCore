## Discount workflow: e2e suite + fix the reported blocker (cancelled-with-sales rule)

**Root cause of your report (traced in code):** create D1 → sale (frozen with `discount_id = D1`, correct) → cancel D1 → create D2 over the same dates → **409 DISCOUNT_OVERLAP**, because the overlap check blocks "cancelled-with-sales" ranges forever (`pd.status='active' OR (pd.status='cancelled' AND EXISTS sale_items)`). That's the documented AGENTS.md §10 rule, but the error says *"overlaps with an existing **active** discount"* — misleading, and the permanent reservation is the real pain. Decision confirmed with you: **relax the rule**.

### Implementation

**1. Relax the overlap rule** (`discountService.create`): the overlap check keeps only `pd.status = 'active'` (drop the cancelled-with-sales clause). A cancelled discount — with or without sales — never blocks a new discount. Historical sales keep their frozen `discount_id`, `unit_price`, and `original_price`, so reports/units-sold/savings are unaffected. Bonus: the existing 409 message ("overlaps with an existing *active* discount") is now always literally true — no i18n change needed.

**2. Spec update** — AGENTS.md §10 is internally inconsistent (one sentence blocks cancelled-with-sales, another says cancelled never counts). Remove "cancelled-with-sales" from the overlap sentence; the inclusive same-day boundary stays.

**3. Unit test updates** — `discountService.test.ts`: the test asserting a cancelled-with-sales discount blocks a same-range recreate flips to expect success; the cancelled-without-sales and same-day-boundary tests stay.

**4. New e2e suite** — `backend/test/integration/discounts.test.ts` (supertest, following `http.test.ts`'s env-stub → `initDatabase()` → `createApp()` → service-login token bootstrap): the full workflow and edge cases over HTTP:
- **Happy path**: create D1 (today) → product effective price discounted → sale charges discounted price with `discount_id`/`original_price` frozen → cancel → effective price null → **the historical sale is unchanged** (unit_price, discount_id intact) → discount history shows units_sold.
- **The reported scenario, post-fix**: sale on D1 → cancel → recreate D2 over the SAME range → 201 → D2 applies to the product and to the next sale; the old sale still references D1.
- **Edges**: active overlap → 409; inclusive same-day adjacency → 409; start the day after D1 ends → 201; cancel without sales → same-range recreate → 201; double cancel → 400 ALREADY_CANCELLED; delete without sales → gone; delete with sales → 409 DISCOUNT_HAS_SALES; price ≥ sell_price → 400; discontinued product → 400; unknown product → 404; scheduled (future) discount → no effect today (normal-price sale, `discount_id` null); mixed sale (discounted + non-discounted items) → per-line independence; discount history aggregates units_sold across two sales.

**5. Verification** — full backend suite + typechecks (the e2e file is auto-included by vitest); frontend untouched (no build needed, but lint/build run cheap as a sanity check); no i18n changes; MEMORY.md Phase 35 with the findings list.
